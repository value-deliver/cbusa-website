# carsbuyusa.com

Company website for Cars Buy USA Inc. Static HTML, generated by `build.py`, served by GitHub Pages
from `docs/`.

Built to satisfy bank compliance checks on incoming international wires: a compliance officer
holding one of our invoices must be able to confirm, from this site, that the company is real, is
the entity named on the invoice, and does the thing the payment is for. Design rationale and
constraints are in `spec/2026-08-14-carsbuyusa-website-design.md`.

## Build

```
python build.py
```

Standard library only, no dependencies. Writes 15 pages (5 pages × 3 languages) into `docs/`, plus
`CNAME`, `robots.txt`, `sitemap.xml`, and a single-file review copy at `preview.html`.

Preview locally:

```
cd docs && python -m http.server 8765     # then open http://localhost:8765/
```

## Editing

**All copy and company facts live in `content.py`.** Nothing is edited in `docs/` — that directory
is deleted and regenerated on every build.

Company identity facts are defined once, in `FACTS`, and rendered into all fifteen pages. Change a
fact there and it changes everywhere, in every language, at once. This is deliberate: the site's
whole purpose is that its details match the invoice, so they cannot be allowed to drift.

The build fails rather than publishing if a translation gains or loses a section, and omits any
fact that is `None` instead of printing a placeholder.

## Deploy

Once, to create the repository:

```
git remote add origin git@github.com:value-deliver/carsbuyusa-website.git
git push -u origin main
```

Then in the repository settings → Pages: source **Deploy from a branch**, branch **main**, folder
**/docs**. Add `carsbuyusa.com` as the custom domain and tick **Enforce HTTPS** once the
certificate is issued.

Every later deploy is just:

```
python build.py && git add -A && git commit -m "update site" && git push
```

## DNS

> **Do not touch the MX records.** `carsbuyusa.com` runs Google Workspace and company email is
> live. Only the records below change. Editing MX breaks company email, which during a
> payment-verification check would be the worst possible moment.

At the DNS host for `carsbuyusa.com`, add:

| Type | Name | Value |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| AAAA | `@` | `2606:50c0:8000::153` |
| AAAA | `@` | `2606:50c0:8001::153` |
| AAAA | `@` | `2606:50c0:8002::153` |
| AAAA | `@` | `2606:50c0:8003::153` |
| CNAME | `www` | `value-deliver.github.io` |

Verify afterwards that email still resolves — this should list Google's mail servers, unchanged:

```
nslookup -type=mx carsbuyusa.com
```


## Rules for this site

- **Never publish bank or wire details.** They belong on the invoice sent to the client directly. A
  public page carrying them is raw material for payment-redirection fraud against our own clients.
- **Never claim a licence, certification, or membership we don't hold**, and never publish a figure
  the owner hasn't confirmed — years in business, cars sourced, client names, testimonials. A site
  caught inventing detail fails the check it exists to pass.
- **Keep the details identical to the invoice template** (`../cbusa-audit/templates/agreement.html`).
  If the invoice header changes, change `FACTS` to match in the same session.
